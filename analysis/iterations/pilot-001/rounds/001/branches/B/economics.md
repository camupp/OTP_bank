# Общая модель для двух концепций

Это приложение к CON-003@v1 и CON-004@v1; оно не назначает им преимущество. База путей к источникам — корень проекта OTP_bank. Источники правил: замороженный `analysis/iterations/pilot-001/rounds/001/inputs/baseline.md`, разделы «Роли и права», «Начисления Коинов», «Деньги, накопления и целевые показатели»; первичный C01, физ. с. 9–12, 19. Все параметры без значения — неизвестные, а не нули. Проектные допущения B-A01–B-A12 сохранены в `assumptions.csv` рядом.

## Единицы, период и сопоставимость

Расчётный шаг — месяц, квартальное обнуление выделено отдельным событием; закупочный лимит — календарный год. Штат, роли/география, начальные личные C0/R0 и невыданные F0, календарь событий, цены наград в валюте, закупочные цены, наличие, открытые обязательства и мощности берутся на одинаковую дату для BASELINE и всех кандидатов. Их значений в пакете нет. Начальные значения Q3 из кейса нельзя использовать как новый общий F0 без даты и словаря событий.

В обычном сценарии подставляются одни и те же внешние входы и одинаковые поведенческие параметры; меняются только объяснимые механизмом события. Это символический сценарий, не наиболее вероятный прогноз. Отдельно нужна чувствительность к изменениям числа Thanks, W_R, конвертации и погашения; сами концепции не доказывают знак или размер изменений.

## Журналы и балансы

1. Признание: event_id, дата действия/признания, участники, конкретный вклад, основание, видимость, принятие/ошибка/оспаривание. Нет автоматической денежной оценки текста.
2. Валютные события: event_id, связанный recognition_id при наличии, валюта, тип, исходный/целевой счёт, сумма, дата проводки, статус, основание, автор, id исходной операции для исправления. Один event_id не проводится повторно.
3. Фонды: manager_id, квартал, G_R, W_R, возврат/исправление и квартальный L_R. Фонд не является личным R руководителя.
4. Заказы/исполнение: SKU, количество, цена C/R, резерв/списание/возврат, доставка или слот льготы, дата исполнения. Резерв и списание различаются; источник должен дать действующий момент списания.
5. Деньги/ресурсы: поставщик, заказ закупки, количество, фактическая цена, дата платежа, статья, складские движения; часы исполнителей и замещения. Нельзя восстановить этот журнал умножением валюты на 0,2 рубля.

Для периода t, на уровне сотрудников либо в сумме:

```text
C1 = C0 + I_C + X_RtoC + T_in - T_out - P_C + V_C + J_C
R1 = R0 + W_R - X_RtoC - P_R + V_R + J_R
F1 = F0 + G_R - W_R - L_R + J_F
```

I_C — только новая эмиссия; G_R — пополнение невыданного фонда; W_R — выдача из фонда в личный R; X_RtoC — конвертация 1:1; P_C/P_R — валовое списание при получении награды согласно подтверждённому событию; V_C/V_R — возврат прежнего списания; J — отдельно подписанные исправления с причиной. T — передача уже имеющихся C, сумма T_in−T_out по системе равна нулю. Изменение видимости признания не является J.

W_R проводится одновременно −F/+R; X одновременно −R/+C. Возврат ошибочной выдачи, если он допустим по регламенту, — связанные J_R=−z и J_F=+z, а не новая эмиссия и не автоматическое отбирание средств. Через границу квартала такой возврат требует отдельного утверждённого правила: нельзя восстанавливать погашенный фонд произвольно. Спор сам по себе ничего не списывает. Возврат покупки восстанавливает исходную валюту, но не повторяет конвертацию и не считается ещё одним I_C. Никаких массовых отрицательных J ради бюджета.

В конце квартала L_R равен положительному невыданному фонду непосредственно перед обнулением; после события F=0. C/R сотрудников не обнуляются. Каждый расход ограничен доступным остатком на момент события, с учётом действующих резервов. В частности, после всех допустимых выдач и исправлений X_RtoC+P_R не может превысить доступный R: одна R-единица используется либо прямо, либо для C.

Сумма трёх запасов в условных внутренних единицах:

```text
S1 = S0 + I_C + G_R - P_C - P_R - L_R + V_C + V_R + J_C + J_R + J_F
```

Это проверка единиц и сохранения, не стоимостная оценка обязательства в рублях. Для каждой валюты нужны также сверка по людям, нулевые остатки необъяснимых проводок и отсутствие отрицательных доступных счетов.

В обоих кандидатах все ставки событий сохраняются. Для Thanks отдельная часть I_C при подтверждённом правиле событий:

```text
I_Thanks,t = 50 × Σ_i min(n_send,i,t,5) + 100 × Σ_i min(n_receive,i,t,5)
I_C = I_Thanks + I_other
```

n — подтверждённые события соответствующего основания у каждого человека в месяце, не все сообщения/ответы/номинации. Максимум двух оснований вместе — 750 C на человека в месяц; это математический потолок по с. 11, не ожидаемая эмиссия. До восстановления связи Thanks/перевода/бонуса фактические n неизвестны. I_other включает все остальные основания с действующими ставками; неоднозначный стажевый календарь нельзя складывать автоматически.

## Деньги и награды

Для SKU j: a_j — цена одной награды в C либо R, p_j,t — закупочная цена в рублях, q_j,t — выданные единицы, b_j,t — закупленные единицы, v_j,t — доступный склад. Доставка, порча и возвраты имеют отдельные движения. Для наград за C: P_C=Σ a_j q_j, но закупки могут предшествовать погашению; для прямых R-наград P_R=Σ a_j q_j. Одна награда принадлежит только своему пути оплаты.

Закупочная касса года K_y=Σ фактических платежей поставщикам мерча/сертификатов в году y минус фактические денежные возвраты, если правила бюджета разрешают их зачёт. Уже оплаченный склад не оплачивается второй раз; будущие платежи по договорам остаются обязательствами. Склад: v_end=v_start+b−q−списания+возвраты, с календарём доступности. Резерв закупочного лимита не равен отрицательному расходу. Проверка одновременно для L=30 000 000 и L=34 000 000 руб./год: K_y≤L, с отдельным показом запаса L−K_y. При K_y>30 млн и ≤34 млн выполнена только верхняя граница; нижняя не пройдена. Фактический утверждённый лимит неизвестен.

Полная стоимость FC_y=K_y+платформа+интеграции+поддержка+логистика вне закупочной статьи+стоимость времени сотрудников/руководителей/HR+исполнение льгот и замещение. Каждая статья относится ровно один раз: включённые в закупочную цену доставка/работы повторно не добавляются. Для внутреннего времени H_role×r_role показывается ресурсная оценка, отдельно — дополнительный cash: сверхурочные/подряд/замещение. Без новых выплат время всё равно имеет альтернативную стоимость. Входные r, H, утверждённые лимиты рабочего времени и дата платежей неизвестны.

## Общие стрессы и границы

| Сценарий | Одинаковая постановка для всех вариантов | Условие несостоятельности |
|---|---|---|
| S0, обычный символический | Общие C0/R0/F0, I_other, цены, календарь; W, n_Thanks, X, P заданы как переменные, без вероятности | Невыполнимые остатки, бюджет либо мощность; отсутствие входа оставляет uncertain |
| S1, старые C | Дополнительное погашение d_C из начального C0; 0≤d_C≤ещё не использованная часть C0, остальные изменения отдельно | Не хватает оплаченного склада/закупочного запаса либо доступа к награде |
| S2, конвертация R | Отдельно от S1 увеличить X вплоть до всего доступного R; P_R для этих единиц=0; проверить последующее P_C и отсроченный спрос | Конвертация сохраняет единицы, но увеличивает потребность в C-наградах сверх K_y/мощности |
| S3, прямые R | Альтернативно S2: X=0 для стрессуемого R, максимум возможного прямого P_R с реальным составом наград/ролей | Нехватка разрешённых слотов, часов замещения, операционной мощности; нельзя назвать выходной бесплатным |
| S4, цена/доступ | p_j→p_j(1+π_j), π_j≥0; падение поставки и исполнения до заданного уровня, в том числе нуля, без скрытой смены состава людей | K_y>L, отрицательный склад, недопустимое ожидание/замещение; старые права не аннулируются |

Для иллюстрации границы фиксируем **допущение** о составе дополнительного C-погашения: h_j — доли C, Σh_j=1. Дополнительные количества q_extra,j=d_C×h_j/a_j; после свободного склада s_j закупка max(0,q_extra,j−s_j). При оплате в том же году дополнительная касса ΔK=Σ p_j max(0,d_C h_j/a_j−s_j). Кандидат проходит сценарий при ΔK≤L−K_base для ОБОИХ L, а не благодаря выбранному 34 млн. При отсутствии свободного склада и фиксированной корзине e=Σh_j p_j/a_j руб./C, d_C≤(L−K_base)/e. При отрицательном запасе бюджета сценарий уже не выполнен. При ином календаре платежа формула переносится на его год, а не исчезает. Аналогично дополнительная выдача ΔW_R при доле последующей конвертации x и C-погашения r добавляет приблизительно ΔW_R×x×r C спроса в указанном периоде; x,r∈[0,1] — чувствительность, не коэффициенты банка.

Для прямых льгот k доступна мощность A_k,role,t в слотах/часах: q_k≤A_k,role,t; Σq_k h_cover,k≤доступные часы замещения. Дефицит нельзя закрывать недоступной отдельным ролям удалёнкой. Очередь и сохранение остатка не доказательство исполнения права. Если награды нельзя исполнить с сохранённой ценностью, результат — operational/budget uncertain или fail по проверенному сценарию; внедрение механизма откладывается, право сотрудника остаётся.

## Нормированная проверка сохранения

**Расчёт, не данные ОТП и не денежный сценарий.** На искусственный квартал C0=1000 C, R0=400 R, F0=600 R; I_C=150 C, G_R=500 R, W_R=300 R, X=100 R, P_C=200 C, P_R=50 R, T_in=T_out=40 C, J=V=0. Перед обнулением C1=1050, R1=550, F1=800. После L_R=800: F1=0; личные C/R неизменны. S1=1600=2000+150+500−200−50−800. Это одинаковая иллюстрация для двух концепций, никакого «выигрыша» в ней нет. Отдельные допустимые крайние пути одного доступного R проверяются в `validation.json` рядом.

## Что передать финансовому аналитику

Для CON-003 изменяемые каналы: n_Thanks и их распределение по людям, T, поведенческие X/P; плановый G и решение W не меняются механически. Для CON-004: набор получателей/оснований/время W; суммарный W может измениться при прежнем G; номинации сами дают ноль I_C, ноль W. Оба кандидата сохраняют I_other, ставки, квартальное обнуление и старые права. Остальные потоки могут поведенчески измениться — это измеряемая чувствительность, не гарантированный ноль.

Запросы данных: (1) остатки/резервы и журнал проводок на общую дату; (2) словарь событий Thanks/переводов/стажа и регламент исправлений; (3) фонд/численность/полномочия; (4) a_j,p_j, остатки, договоры и календарь; (5) доступность льгот и мощности по ролям/регионам; (6) ставки и рабочее время реализации. До получения этих входов реальные `budget` и `currency_balances` — **uncertain**. Проверенная символическая арифметика не меняет этот вывод.
