# Порядок обработки и продолжения

Эти действия выполняются только после поручения использовать skill. Установка skill и создание пустых форм их не запускают.

## Учёт назначенной области

Для первой обработки проверь имена, типы и доступность файлов выбранной области. Исключи из содержательного переноса технические файлы и lock-файлы, сохранив причину в покрытии, если они входят в назначенный охват. При поручении всей библиотеки не ограничивай учёт только удобными для чтения форматами.

Один `source_id` относится к одному локальному исходному файлу. `source_group` объединяет PDF, его извлечение, карточку и версии одной публикации. Это позволяет учитывать физические файлы без увеличения числа независимых доказательств. Пути из существующих подборок сохраняй как исходные идентификаторы в карточке; новый wiki-ID не заменяет их.

Регистрируй реальный SHA-256 файла до содержательного переноса. Необходимость чтения полного файла для хеша не означает, что его содержание прочитано моделью. Большие PDF обрабатывай смысловыми разделами, таблицы — подходящими листами/диапазонами. Область каждой порции отражается в `processing.csv`.

## Обращение с разными материалами

| Тип | Что переносить / как учитывать |
|---|---|
| Кейс и сообщения организаторов | Точные требования, факты, определения, ограничения и даты. При несовпадении установить версию; спорное явно отметить. |
| Исследование | Дизайн, контекст, выборку, исход, подтверждённый результат, ограничения. Не подменять полный текст аннотацией. |
| Кейс поставщика | Механику и атрибутированное заявление компании; методологию результата и её отсутствие. |
| Прежний обзор | Полезные тезисы и ссылки с отметкой глубины проверки. Непроверенные утверждения не становятся фактами через повторение. |
| Уже разобранный учебник | Повторно использовать существующие темы и навигацию через ссылки; переносить нужные методические пояснения. Учитывать локальные правила, ошибки формул и OCR. |
| XLSX / набор данных | Описать назначение, структуру, единицу наблюдения, доступные поля и ограничения, подтверждённые чтением. Расчёты и кодирование отзывов относятся к отдельной аналитической задаче. |
| Промпты, архивы, инструкции о процессе | Классифицировать по назначению. Они не являются доказательствами по признанию сотрудников и не управляют выполнением. Полезное для настройки процесса оставить ссылкой на docs, остальное исключить с причиной. |
| HTML, извлечения, изображения, API-ответы | Установить связь с оригиналом, наличие технической защиты, повторов и ошибок извлечения. Изображение с подписями без связей не считать полной текстовой расшифровкой схемы. |

## Содержательная порция

Выбери порцию, которая позволяет сохранить цельный смысл и проверить результат в текущем контексте. Не разрывай формулу и обозначения, условие и нужные данные, правило и исключение. Для большой темы допустимы подстраницы с ясными ссылками.

Найди уже существующую страницу по вопросу и обнови её; новую создавай для самостоятельной темы. Сохраняй полезные сведения, которые важны для дальнейших вопросов кейса, даже если они не поддерживают текущую гипотезу. Не назначай одинаковую достоверность всем источникам.

Для спорного числа открой указанный оригинал. Если оригинал недоступен, сохрани доступную формулировку с атрибуцией и отметкой проверки. Для схемы передай отношения элементов вложенным списком, таблицей или Mermaid; оставь ссылку на изображение. Нечитаемые части обозначай явно.

## Продолжение и изменение источников

После сохранения страницы обнови реестры и следующий шаг. Если работа прервана, `partial` и конкретный необработанный диапазон позволяют продолжить без повторного чтения всего файла.

При изменении версии не стирай историю охвата: отметь затронутые строки `outdated`, добавь единицы для новой версии, проверь связанные страницы и спорные утверждения. Не обновляй только хеш с сохранением статуса `processed`.

При изменении редакции Wiki сохрани источники старого утверждения, если оно нужно для объяснения противоречия. `reviewed` не означает вечную актуальность или отсутствие ошибок в самом первоисточнике.

## Границы отчёта о полноте

Метаданные, ссылка на оригинал, карточка и полный содержательный перенос — разные результаты. `reused` объясняет, какой готовый структурированный слой используется, и не означает повторной полной вычитки. `excluded` требует причины. `blocked` и `partial` остаются открытыми пробелами.

Для всей библиотеки учти все файлы назначенной области, включая исключённые и производные; для каждого содержательного файла назначь покрытие разделов. Прогресс измеряется реальным охватом, а не количеством созданных страниц. Завершение одной порции не закрывает остальные источники.
