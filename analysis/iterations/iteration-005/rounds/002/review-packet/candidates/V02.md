V02. Все нормы, минуты, календарь и примеры ниже — **проектные допущения**; суммы и таблицы — **расчёты**. Факты кейса обозначены отдельно. ## 1. Проблема, основания и проверяемая гипотеза

Факт сообщения: в T1335 сотрудник просит понятные критерии R. Наблюдение не устанавливает распространённость несправедливости. Факт кейса: Q3 фонд38,54 млн R, передано19,427591 млн R; невыданный остаток не доказывает отсутствия заслуг (frozen evidence C03/C08). Нужны личный путь «что сделать — кто проверит — сколько получу» и независимая проверка, посильная для всех ролей.

Гипотеза: гарантированные500 R за принятый полезный результат, конечный отделовой top и отдельный необычный вклад делают путь понятнее; готовый независимый акт снижает повторную приёмку. Эффект для ОТП не измерен. Предмет редакция — однозначность качества и уровней, достижимость при малом n, повторное использование достаточного акта и честная полная стоимость доказательств. Гипотеза не требует роста каждого KPI либо бесконечного улучшения сильного сотрудника.

## 2. Механика признания, валюты и администрирование

**Открытый доступ.** Все7200 сценарно eligible, включая HR/начальников, распределены по домашним сопоставимым группам до усилия; нет набора первых300. Расчётная структура120 групп≤60 человек, три когорты по2400. Каждый получает четыре полных трёхмесячных окна. Один человек — одна домашняя группа/карточка/когорта на окно. Большие отделы делятся сначала по профессии/возможностям, затем по устойчивому реестровому коду; никого не исключают. Подгруппы и маршруты не выбирают после результата.

**Личная база.** За L1 и выше каждый выполнивший получает500 R за окно независимо от места; максимум2000 R за четыре окна. До начала доступны два самостоятельных пути: измеримый результат либо принятый полезный milestone. При обоих есть обязательное качество. Несколько результатов не умножают базу. Самономинация — сообщение root-ID/ссылки, разрешена всем; сумму и собственное подтверждение назначать нельзя.

**Точный словарь метрического пути.** Карточка содержит целочисленные case-ID, назначение до результата, класс сложности, источник, контрольный список и эталон времени. Знаменатель n — все назначенные и завершённые в окне задачи данной очереди/класса, включая возвраты/повторные открытия; исключения только по заранее объявленному отсутствию экспозиции, с другим подписантом. Неоконченные задачи и пропавшие банковские записи показываются отдельно; участник не удаляет их из знаменателя. При недостаточном полном n или неизвестном исходе расчёт pending, а не искусственное100%. Для финальных случаев наблюдают повторный контакт7дней (поддержка) либо возврат/повторное открытие10дней (бэк-офис/IT); финализация через10дней после полного окна.

- **s/n — полезный исход:** s задач приняты с первого предъявления без повторного обращения/возврата/повторного открытия в заданный срок. Это результат процесса; косметический возврат может уменьшить s без нарушения обязательного контроля.
- **q/n — соблюдение качества:** q задач без некритического нарушения заранее перечисленных обязательных контролей по независимому акту. В одной задаче несколько нарушений дают один неуспех q. Критические нарушения безопасности/клиентского ущерба считаются отдельно: допустимо0. Качество требует `100q≥98n`, без округления процентов; контролируется весь знаменатель, не удобная выборка. Отсутствующий обязательный контроль — не «нет дефекта», а pending до восстановления.
- **r — нормированное время:** для каждого case берутся зарегистрированные миллисекунды от начала до финального принятия, включая собственную переделку; делятся на положительный эталон того же класса/сложности/смены. Только независимо подтверждённые системные простои исключаются по одной норме для всех. Эталоны — проектные воспроизводимые тесты, подготовленные до окна; фактической истории банка не предполагаем. Сортируют все n отношений; берут **верхнюю медиану**, элемент `floor(n/2)+1` при счёте с1. Сравнение дробей точное, без округления отображаемой скорости.

Уровни применяются **после одного и того же порога s, q и critical=0**: L1 — r>0,95; L2 — 0,90<r≤0,95; L3 — r≤0,90. При невыполненном качестве/исходе — L0 независимо от скорости. r>1 не закрывает L1 при полезном качественном исходе. Быстрота не может компенсировать ухудшение качества. Это новая шкала: соседние уровни различаются независимым непрерывным признаком. При малом n не вводятся недостижимые соседние процентные уровни. Не утверждаем статистическую значимость разницы двух работников по десяти задачам; это объявленная нормативная ступень, а не оценка истинной способности.

Все L1/L2/L3 остаются достижимы при одном и том же допустимом q. Данные q и r берутся из независимого полного акта; QA-выборка10% ниже относится только к проверке пригодности готового акта, **не заменяет первичную QA всех случаев**.

**Milestone без личной базы.** Одна единица — самостоятельная полезная инструкция/контрольный шаблон/тест/запрос/дашборд с одним root-ID пользы: заранее определённый потребитель и задача,10 назначенных эталонных случаев с полностью правильным ожидаемым выходом,2 успешных воспроизведения другим человеком,2 реальных использования и30дней без критического дефекта. QA обязательных контролей98% по всем случаям единицы,critical0. Лайки и красивая заявка не заменяют использование. Поддержка — инструкция по повторной проблеме; бэк-офис — воспроизводимый шаблон; IT — тест/запрос с эталонным результатом. L1=1, L2=2, L3=3 независимых принятых единицы, максимум3. Три контрольных этапа большой задачи допустимы лишь если каждый заранее имеет отдельную принимаемую пользу; дробление одного действия после факта запрещено. Условия30дней должны завершиться в полном окне; позднее внедрение переходит в следующее окно без потери уже принятого факта, но не даёт ранней награды без обязательного качества.

Нехватка входящего потока не закрывает людей: до окна доступен этот полезный маршрут с тестовыми обезличенными случаями и реальным пользователем. Заранее оплачивается отдельный top-трек по численности выбравших карточку; сырые r метрик и числа artifacts не сравниваются. Если временно отсутствуют пользователи/приёмщик, это реальный предел доступности, который фиксируют до обещания; данные не приравнивают к0.

**Одна достаточная приёмка.** Акт содержит root-ID, личный вклад/доли, карточку/версию, окно, n/s/q/critical/r либо тесты/использования/30дней, финальные даты, независимого подписанта и hash. Исполнитель и подписант не получают выгоды от подтверждения своей суммы. Заявка не заменяет акт.

Пакетная сверка группы10мин HR и10мин владельца — проверка roster/мест/суммы, не повторная QA каждого результата. Сбор тестов/полезного артефакта/приёмка/сверка — четыре разные статьи. Максимальная норма3единицы применяется и к трудовому стрессу, а не среднее1удобная единица.

**Конечный top.** Пул группы h≤60: `250h R/окно`, все группы1,8млн/цикл. Слоты1/2/3 = половина/треть/остаток пула; при h60 это7500/5000/2500. Допускаются L2/L3, сортировка метрик: уровень↓, r↑,s/n↓,q/n↓; milestones: уровень↓, число независимых использований на принятую единицу↓ с cap2 на единицу, затем точная ничья. Число применений выше cap не стимулирует накрутку. В точной ничьей разделяют только занятые слоты1..3 между **всеми** связавшими их участниками. Выплаты до0,01R вниз; остаток F. Нет добавочных мест либо произвольного тайбрейка. Слоты без подходящих участников остаются F. Одиночке доступен только слот1 при L2/L3. Фонд не увеличивается из-за команды/межотделового заказчика.

**Особый вклад.** Вне обычной карточки один независимо принятый внедрённый результат — уровень5000R; документированное принятие двумя процессами/отделами —10000R. Другой владелец пользы подтверждает результат, отдельный держатель фонда применяет ставку и проверяет конечное место; получатель отведён от обоих действий. Месячные пределы20×5000 и10×10000, всего2,4млн/год. Это конечный конкурс, не гарантия суммы всем заявкам: отдельные уровни упорядочены по числу независимых внедрений, затем дате завершения независимой проверки; точные ничьи делят занятые свободные слоты. Уведомление до подачи прямо объясняет возможность дробной суммы. Учитываем40заявок/30принятых в месяц, включая10отказов. Проверка5раб.дней, апелляция5дней другому ответственному; есть заместитель.

**Совмещение/права.** База+top одного результата разрешены и зарезервированы. Special того же корневого результата или прямо оплаченной зарплатной result-премии запрещён; обычная зарплата за должность сама по себе не исключает признание. Другой root-ID special может складываться. Максимум человеку за четыре обычных окна и12месяцев special:2000+30000+40000=72000R; не больше1special/цикл, общий cap проверяют также на доли команд. Один ID пользы связывает отделы/номинации; независимые личные подрезультаты имеют sub-ID, но special-проверка использует общий root. При неделимом общем результате top-единица одна, доли объявлены до работы и суммируются в1. Личную базу получают только отдельно подтверждённые вклады, а не все фамилии в списке.

R→C1:1 без обратного обмена; личные R не передаются, C передаются без создания валюты. Обычные права возникают при выполнении полного окна и окончании качества; independent act уже доказывает право — оно U, даже если банковский лог проводки опаздывает. Posting≤2раб.дней; запрос сразу; ни право, ни запрос не откладывают ради ровной кассы. F обнуляется только в невыданной и не зарезервированной под права/условные обещания части. U, личные остатки, оплаченные/неисполненные заказы и условные обещания ведутся отдельно. В полном максимуме свободного F/истечения0; уменьшение по фактическим незанятым слотам никогда не отменяет уже возникшее право.

## 3. Три пользовательских сценария и точные выплаты

**Сотрудник.** Новичок IT без собственной истории получает ту же абсолютную карточку: n10,s9,q10,critical0,r0,96 → L1,500R. При r0,95 → L2,500R и при первом месте в группе60 ещё7500, итого8000R; это место, а не гарантированная доплата каждому L2. Сильный стабильный n20,s20,q20,r0,89 → L3 с той же базой500 и, при первом месте,8000R; улучшать собственную уже высокую базу не требуется. Без повторяемых задач новичок делает одну полезную принятую единицу →500R; три независимых единицы → L3,право на top по месту. Бэк-офис n60,s59,q59,r0,95 → L2; при втором месте500+5000=5500R. q58 или s58 →L0 до исправления/другого будущего окна, не ложное обещание500.

**Руководитель.** Фиксирует группы, карточки, salary-root mapping и независимых владельцев до окна; получает вычисленный пакет мест/денег, проверяет только конфликты и исключения. Для собственного результата руководитель лишь сообщает факт. Пример принятого нового стандарта в двух отделах: другой владелец подтверждает special10000R, независимый вышестоящий держатель фонда подтверждает место, другой оператор проводит; сам руководитель не меняет сумму/лог. Если обычная карточка уже оплатила тот же root-ID, special0; иной принятый root допускает обычную базу500 +special10000=10500R.

**HR/администратор.** Закрывает roster и календарь, резервирует максимум до усилия, контролирует U/проводку/заказ/получение и бюджетные годы. Его личный dashboard с10тестами,2воспроизведениями,2использованиями/30днями принимает другой процессный владелец, верификацию делает HR-заместитель без выгоды, проводит другой оператор. Один milestone —500R; право не зависит от того, кто администрирует платформу. Изменение логов: before/after,причина,время,другой подписант; собственные поля получателю недоступны. Самономинация не даёт исключения из этого процесса.

## 5. Доступность, интеграции, пики и нежелательные сценарии

Новичок идёт по абсолютному результату или milestone; стабильный высокий — по тем же абсолютным порогам. Личная база прошлых месяцев не обязательна. При неполном времени/отпуске минимальный n не делят механически; доступны меньшие по объёму полезные самостоятельные единицы с тем же качеством. При переводе домашняя карточка заморожена на окно, принимающий владелец может смениться с журналом; двойной базы нет. Роль и регион не закрывают доступ к самостоятельному артефакту и малой награде, но реальную возможность пользователя/приёмщика проверяют до старта.

Внутренний IT и подписанный CSV допустимы; готовые API/автоматические экспорты не факты.
