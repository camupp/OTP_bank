# От источника к праву и проводке CON-021@v2

1. До усилия владелец роли утверждает scope/правило/дату; диспетчер назначение; HR — объективную когорту/личное окно/домашний пул. Получатель не меняет собственную ставку/долю/порог.
2. Экспорт: event/case/root/deliverable, версии, period/subject, acceptance/use, inspection_id, личные дни/доли. Source_manifest контролирует count/hash/availability. Потерянная партиция не QA 0, дубли/версии/коррекции не новая польза.
3. QA-владелец проверяет существующий акт по объекту/scope/периоду/рубрике/независимости/зрелости. Недостающее покрытие проверяется отдельно с ценой, не 20 новых QA каждого; critical полного реестра не угадывается по малой выборке.
4. evaluator.py применяет metrics-spec.json без усмотрения. Для обычного обязательства используются plan/accept/use, missing bundle не синтезируется; проектный existing акт достаточен normal. Новый признак только там, где существующий акт его не покрывает.
5. Личные экспозиция/доля/окно/конфликт отдельно от командного QA. Actual self-edit/sign/post→pending, alternate_id — ещё не подпись. Без фактического signed_at нужного posting-review действия расчётный допуск остаётся pending с условным резервом, не sanctioned U. Непустые editor/signer/operator должны быть разными, вне всей команды и её явно указанных reporting_to. Type_correction не posting-review. Правильный независимый review создаёт authorized U, реальной проводки в source нет.
6. Пакет: employee/window/cohort; rule/source versions и SHA/locators; benefit/root; семья/группа/экспозиция; QA scope/inspection IDs; normal/stretch-state; rank/tiesize; pool/share/rounding/R; независимый верификатор и другой HR-оператор/время. Без клиентских деталей.
7. G — два passed фиксированных квартала. Личный fail не переносит пару; потерянный источник сохраняет максимум исходного окна. Неизвестный конкурент удерживает top, не G других. Конфликт члена команды удерживает его долю, не повышает чужую.
8. HR проверяет лимиты/арифметику/даты/дубли/средства и проводит U→R. Конвертация/заказ/вручение отдельно. Идемпотентность по employee/window/channel/benefit запрещает повторную проводку пакета. Исправление: before/after/reason/независимая подпись и пересчёт прежним правилом, доказанные права сохраняются.

traces.json: короткие source IDs и промежуточные значения. unit-decisions.csv: ролевые исходы/QA/CSAT/часы. decisions.csv: личные исходы. window-guarantee.csv: квалификационный пример двух календарныхP, не фактические даты личных окон с 15-го. top.csv: rank/share/R. Posting отдельно. Реальной банковской проводки код не делает.
