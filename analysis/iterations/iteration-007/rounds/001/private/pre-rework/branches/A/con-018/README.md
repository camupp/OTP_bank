# Воспроизведение кандидата

Запуск из любой папки: `python3.12 -B /полный/путь/evaluator.py`.

- `metrics-spec.json` — опубликованные проспективные правила; `evaluate(data, spec)` — функция расчёта только из развёрнутых source-таблиц.
- `concept.md`, `cards.md`, `employee-card.md`, `source-to-award.md` — самостоятельное описание и путь человека.
- `decisions.csv` — 368 личных квартальных решений в base и 22 вариантах; `eligibility` отделён от готовности проводки.
- `money-examples.csv` — фиксированное окно, top, доли, расчётные и независимо подтверждённые U. Pending amount сохраняет расчётную G, удержанную без подписи, отдельно от условного максимума неизвестной квалификации.
- `traces.json` — небольшие образцы и промежуточные поля, без многократного копирования всего raw.
- `finance-spec.json` — денежные инварианты/SHA, точные местные формулировки квалификации и ресурс; `resource-sensitivity.csv` и `peak-resource.csv` — труд и пики.
- `assumptions.csv`, `self-check.json` — допущения, собственные проверки и границы. Это не независимый допуск.
- `changes.md` — lineage/diff; исключить из слепого тела концепции.

P1/P2 — календарные кварталы синтетики. Примеры G и дат не подтверждают реальное личное окно с 15-го. Production требует выгрузки ровно персонального окна. Неизменённый денежный календарь девяти когорт импортируется по восстановимому пути и SHA.

QA census требует исходных проверок, а не одной пятиминутной проверки на человека. При сценарных 30 flow-root/пакет и 4,5 проверок частей/проектный пакет существующий бизнес-QA = 2436 ч/месяц; новый при пригодном reuse 0/50/100 = 4060/2030/0 ч. Объёмы и ресурс не подтверждены банком. Нельзя объявлять прежний бизнес-QA экономией или бесплатно доступным ресурсом.
