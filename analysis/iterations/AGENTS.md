# Правила итераций

- Установка и чтение инструкций не запускают кейс. Реальная работа начинается по прямому поручению `case-iteration`; raw → wiki остаётся отдельным процессом.
- Перед записью открой протокол и контракты skill, задай входы, лимиты, owned_paths. Координатор единолично ведёт state, selection, private mapping и общие реестры.
- Ветки A/B работают отдельно по общим замороженным фактам. Нельзя редактировать входы после begin или скрытно менять ограничения ради улучшения результата.
- Reviewer получает пакет псевдонимов без авторов/прежних рангов. Приватная карта не входит в его задание. Это инструкция поведения, не отдельные права файловой системы.
- Все кандидаты проходят сопоставимые проверки; исходная программа и прежний победитель сохраняются в сравнении. Итог может не содержать победителя.
- После seal снимок не меняй. Для содержательного исправления используй следующий раунд с lineage и объяснением. Проверка хешей и JSON не равна проверке фактов.
- Не обходи лимиты новым run-id. Прерванный раунд сохраняй для продолжения; сбой исполнителя отражай как сбой, не как успешную пустую концепцию.
