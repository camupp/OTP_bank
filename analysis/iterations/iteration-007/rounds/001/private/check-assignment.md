# Независимые проверки первого раунда

База путей — папка этого раунда. Проверять четыре новые версии, неизменённую CON-016@v2 из `../../incumbent/` и BASELINE из `inputs/baseline.md`. Не выбирать победителя и не править авторские файлы. Общие условия — `inputs/`, `supporting/measurement-contract.md`, `supporting/assignment.md`; версии закрепляет `private/versions-before-checks.json`.

## Финансы и ресурс

- Применить `$case-finance`; запись только в `checks/finance.json`, `checks/finance.md`, `checks/finance-for-review.md`, `checks/finance/`.
- Денежную основу шестого запуска можно проверить по хешам, формулам, инвариантам и сохранённым независимым результатам. Не запускать модели запечатанных снимков и не повторять всю большую сетку без новой причины. Независимо проверить новые права/суммы в примерах, фиксированное полугодовое окно, годовую частоту, групповой top и округление. Условные права не исчезают ради бюджета.
- E24: гарантия 18 млн R, top 4,32 млн, special 1,68 млн в год при N=7200. Порог normal может измениться, размер/частота/календарь награды — нет. E36 остаётся чувствительностью с прежними неудачными сценариями; нельзя расширять допуск молча.
- Все версии, включая контроль, оценить при одном составе ролей и пригодности QA 0/50/100%. Отдельно существующая бизнес-работа, новая проверка и администрирование. Не представлять старые 800 QA-часов против нового нуля как доказанную экономию. Непокрытые новые признаки требуют труда даже при готовом исходном QA.
- Общая сценарная база: 7200 = 2400 + 2400 + 2400 участников 480 команд по 5; 180 групп по 40. Личные проверки 2400/месяц в среднем; общие QA-единицы 1760/месяц только при пригодном командном охвате. В маленькой фикстуре по два уникальных участника каждой проектной команды: четыре человека суммарно и восемь строк team_members за два периода. Не переносить это на масштаб. HR/руководитель/сотрудник/IT: 1000/1500/1000/2000 руб./ч. Лимит HR 220 ч/месяц — сценарий, не факт банка. Проверить пики девяти когорт, ×2 работы и 25% замещения.
- Не принимать авторский evaluator как независимое доказательство. Разрешён общий `supporting/fixtures/source/reader.py` для развёртки данных; собственная арифметика и чтение спецификаций. Проверить единицы, достаточность, ранг/ничьи, командное распределение, отсутствие самоподписанных выплат. Сохранить воспроизводимый расчёт и locators.

## Доказательства и измерение

- Применить `$evidence-check`; запись только в `checks/evidence.json`, `checks/evidence.md`, `checks/evidence-for-review.md`, `checks/evidence/`. Результаты — по всем шести ключам.
- Jira/CRM/телефония, поля и нормы — проектные предположения; подтверждённые факты банка проверять по назначенному source brief и точным местам первичников. Повторный общий ресерч не нужен, если нет конкретного пробела.
- Прочитать спецификации и независимо восстановить ключевые расчёты из source-полей; не исполнять авторские evaluator/verify/build. Общий source/reader.py допустим. Oracle доступен только проверяющим: это описание внесённых искажений, а не готовые правильные показатели/награды.
- Проверить base и все F01–F12: размерность worklog/elapsed/capacity; Done против приёмки/использования; совместимость шкал/периодов QA; CSAT с числом ответов; повторная выгрузка/переоткрытие/root; FTE/отсутствия и сложность без двойной поправки; полнота назначенного потока; большой результат против дробления; внешний блок/помощь; проспективная классификация; самоодобрение/замена подписанта; потерянный источник и позднее событие.
- Готовые уровни/решения авторов — проверяемый результат, а не источник истины. Не требовать заранее определённой награды в каждом стресс-тесте: обоснованный pending допустим. Отдельно показать, где это частный пропуск и где механизм систематически не покрывает целую профессию.
- Проверить employee-facing карточки и трассу «поле → показатель → уровень → право → деньги». Normal — абсолютное выполнение объявленного стандарта, а не квота лучших. Разные профессии не ранжируются одним Q.

## Временная граница для обеих проверок

`private/coordinator-source-observations.md`: синтетические P1/P2 — календарные кварталы 2026, а денежная основа использует персональные окна с 15-го. Это разрешённая проверка функций измерения, но не полный сквозной тест фактического календаря начислений. Проверить, что авторские суммы названы условными квалификационными примерами и не выданы за реальные банковские даты. Источники не подгонять.

## Представление результата

Полный отчёт содержит версии и locators; отдельный `*-for-review.md` сохраняет все значимые выводы, ограничения и цифры, но без прежних рангов/авторства/веток/lineage. Использовать ключи кандидатов — координатор заменит их псевдонимами. JSON checks — по контракту skill. Не скрывать несовпадения между авторской декларацией и проверенным результатом. После завершения не менять файлы без точечного поручения.

Уточнение координатора для проверки найденного дефекта: разрешено извлечь конкретную чистую функцию evaluator и вызвать её в памяти на собственной копии данных, без module-level запуска и экспорта. Ожидаемое решение устанавливается независимо по опубликованному правилу и source-полям. Это воспроизведение контрпримера реализации, а не использование авторского self-check как доказательства её правильности. Весь авторский evaluator/verify/build и модели закрытых снимков не запускать.
