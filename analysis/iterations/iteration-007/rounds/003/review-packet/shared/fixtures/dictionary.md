# Словарь доступных источников OTP-SYN-007-v1

Файл `source/base.json` — JSON-объект таблиц (массивов строк). Grain ниже — исходный grain, а не готовая единица заслуги. Строки patch имеют тот же словарь; запись `null` означает неизвестное/неприменимое значение, которое следует различать по контексту. Отсутствие ответа задаётся `responded=false`, отсутствующий файл — в manifest. Все ID условные; денежной единицы/сумм здесь нет. Все численные/календарные нормы — допущения SF01–09.

Общие поля: `period_id` P1/P2 (P0 только намеренно чужой QA-акт в F04); `subject_id` работник S/B или команда T; `family` support/backoffice/project; `version` целочисленная версия записи; `*_at` timestamp ISO с часовым поясом либо дата ISO там, где источник знает только день; `*_date`, `*_from`, `*_to`, `start/end`, `quality_close` — календарная дата. `window_id` и `cohort_id` — закреплённые идентификаторы личного окна/когорты, не год создания новой награды. `source_ref`/`*_ref` — условная ссылка на сценарный рабочий регистр, не URL настоящей системы. Минуты/часы названы в именах. Доли — число0…1; `fte` — эквивалент полной занятости, у команды может превышать1.

## period_rules

Grain: утверждённая версия источникового правила × семейство × квартал; ключ `rule_id`. `start/end` — включительные границы наблюдаемой работы; `quality_close` — крайняя сценарная дата закрытия качества, не универсальное правило признания поздних фактов. `rule_version`, `classifier_version`, `standard_version` — ссылки на зафиксированную схему/классификатор/инженерную норму. `standard_owner`, `approved_at`, `source_ref` — независимый сценарный владелец/дата/основание; `timezone` — интерпретация дат. `comparison_group_id` связывает заранее определённую группу. `annual_window_start/end` — неизменные границы одного W2026-A.

`stratum_allocations` — список заранее закреплённых страт: `type_id`, `capacity_share` (доля мощности наблюдаемой работы), `mix_weight` (проектная доля смешанного инженерного стандарта), `standard_units_per_hour` (инженерная скорость, ст.ед./ч). Суммы долей/весов равны1; повторно взвешивать уже пересчитанные единицы не предписано. Кандидат выбирает и раскрывает допустимую интерпретацию. `process_service_contract_share=0.95` — контракт SLA операций, не уровень/право награды. `outcome_followup_days=14` — сценарный горизонт последствий. `sampling_seed`, `seed_published_at`, `seed_publisher`, `registry_frozen_at` — воспроизводимые исходные реквизиты старой хеш-выборки; алгоритм выборки здесь не исполняется. Seed публикует QA-владелец после заморозки реестра.

## classifier

Grain: версия класса работ; ключ `class_id` (совпадает с `type_id` в этой версии). `standard_units` — инженерный вес одного исходного случая, не число QA-актов, не готовая ценность. `engineering_minutes_per_standard_unit=60`, `unit=standard_work_unit` задают размерность. `complexity_owner`, `approved_at`, `effective_from`, `version` указывают независимое проспективное утверждение; `employee_editable=false` — право на изменение классификатора. Оно не препятствует ошибочной переклассификации конкретного события F06, которая видна в аудите.

## roster_capacity

Grain: закреплённая мощность субъекта × квартал; ключ `capacity_id`. `entity_type` employee/team, `role` — сценарная роль. `hire_date/transfer_date` — известные даты, null у переноса означает отсутствие переноса именно в этой базовой записи. `scheduled_hours` — **суммарные часы уже с учётом FTE** по графику, до отпусков/обучения/исключений, за данный период членства; `fte` — справочная штатная доля, не второй множитель часов. `leave_hours` и `training_hours` — раздельные непересекающиеся плановые отсутствия за период, часы. `allocation_fraction` — заранее заданная доля оставшейся мощности на изучаемый поток/проект; не готовое фактическое время. Имеющиеся исключения — отдельные интервалы, алгоритм должен обосновать порядок вычитания. `active_days` — календарь запланированных личных рабочих дней, не число закрытых задач. `schedule_version`, `registered_at`, `capacity_owner` — происхождение roster. `assignment_history_status` — полнота назначений на уровне мощности; история конкретных событий может отдельно отсутствовать.

## team_members

Grain: личное участие × закреплённый период членства; ключ `membership_id`. `team_id/employee_id` — команда/член; `fte` — личный FTE в команде, `contribution_share` — проспективная доля одного командного результата/пула, сумма по команде≤1. Это **разные поля**: доли не рассчитываются автоматически из FTE. `personal_active_days`, `role`, `effective_from/to`, `approved_by/at` — экспозиция и независимое назначение. `window_id/cohort_id` остаются личными при переходе. F12 меняет только членство P02 во втором квартале, обновляет мощность команд, оставляет незаполненную долю T01; она не отдаётся другим.

## worklog

Grain: последняя выгруженная редактируемая запись субъекта × квартал; ключ `worklog_id`. `hours` — записанные самим субъектом часы, **не roster**. `completeness` declared_complete/partial — декларация полноты, не доказательство. `editable_by`, `edited_at`, `version`, `previous_hours` — история изменения. В F02 новая версия хранит прошлое значение; база сохраняется как отдельная исходная версия. Ни worklog, ни переработка сами по себе не доказывают дополнительный результат.

## capacity_intervals

Grain: зарегистрированный непрерывный интервал исключения; ключ `interval_id`. `kind` external_blocker/help_other_team; `start_at/end_at` — полуоткрытый интервал [start,end), применим к субъекту. `requestor_id`, `recorded_by`, `approved_by` и `source_ref` нужны для проверки независимости, а не поле independent=true. `recipient_team_id` — кому помогали, null у blocker. В F08 два2-часовых интервала пересекаются на1ч: их объединение имеет3ч, это проверка календаря, не заранее рассчитанный знаменатель Q. Самостоятельная запись без подписи не устанавливает факт исключения. Перенос времени на другой поток не создаёт второй командный результат/пул.

## work_events

Grain: исходное событие/изменение статуса; ключ `event_id`. `source_record_id` — ключ записи в классе исходной системы `source_system_class`; `version` — версия записи; `event_at` — дата фактического статуса. `case_id` — операционный случай; `root_id` — доступная связь одной причины/результата, `parent_id` — эпик/родитель; null означает неизвестную связь, не новый независимый root. `duplicate_of`, `reopen_of`, `correction_of` ссылаются на исходный **case_id**, а не QA/event_id. Несколько версий/статусов не несколько результатов.

`assigned_at/by`, `assignment_history_status` — источник назначения/его полнота; `queue_id`, `channel`, `type_id` — условия сопоставимости и инженерный класс. `due_at` — срок. `status` resolved/Done/reopened — статус трекера, не доказанная приёмка/использование. `accepted_at/by` — доступная приёмка; в проекте расширяется отдельным project record. `external_blocker_ref` — ссылка на capacity interval, не готовая льгота. F05 содержит один **точный физический дубль** event_id с тем же содержимым; это допустимая ошибка выгрузки для проверки, не уникальное событие. В остальных базовых таблицах ключи уникальны. Назначение не равно editable worklog.

## support_outcomes

Grain: обращение × исход (одна запись на случай в базе); ключ `outcome_id`. `case_id` связывает событие, `queue_id`, `topic`, `shift` — контекст. `disposition`, `resolved`, `transfer` — исход; `repeat_of` — доступная связь повтора, null в базовом полностью прослеженном сценарии. `linkage_method=case_root` — способ связывания. `contact_minutes` — длительность контакта как диагностика, не цель признания. `invited` — отправлено приглашение на опрос, `responded` — получен ответ, `csat_score`/`csat_scale` — оценка только ответившего, `csat_at` — дата ответа. `observation_end` — дата закрытия наблюдения по исходу; отсутствие ответа не0. Все обращения и приглашения сохранены, включая неответивших; агрегат средней оценки без знаменателя не дан.

## process_outcomes

Grain: операция × проверка исхода; ключ `outcome_id`. `operation_type`, `mode` — класс/режим. `accepted` и `accepted_at` — факт/дата приёмки, `sla_due_at` — срок. Доля SLA выводима сравнением дат по уникальным принятым операциям; готовой доли в строке нет. `returned`, `return_reason`, `correction_of` — возврат и связь исправления с исходным case; исправление не автоматически новый результат. `external_wait_reason` — известная внешняя причина, null в базе. `observation_end` — граница проверки. В F11 изменены согласованно source event и outcome, без альтернативных противоречащих дат.

## project_records

Grain: результат/часть × версия; ключ `record_id`. `case_id` связывает трекерную часть; `deliverable_id`, `parent_id`, `benefit_id` связывают общий результат. `criteria_ref`, `criteria_agreed_at` — существующее проспективное определение результата. `acceptance_owner/at/ref` — владелец/дата/акт приёмки. `release_ref/at` — релиз. `usage_status` present/missing, `usage_ref`, `usage_observed_at`, `usage_owner`, `usage_coverage` — существующий журнал/подтверждение и область использования; при missing нельзя синтезировать подтверждение.

`usage_units=120` и `usage_measure=distinct_workflow_runs_at_deliverable_grain` относятся к одному deliverable/журналу; повторяются у его частей, **не складываются по case_id**. Они не impact_score/денежная ценность. `defects_ref`, `rollback` — известные дефекты/откат. `story_points` — контекст трекера, не стандартные единицы и не личная ценность. F07 меняет только число частей T01, сохраняя ссылки на один результат/пользу и **одну** независимую проверку; нельзя подменять inspection_id новым для каждого дочернего тикета. В T02 базовые case-проверки действительно отдельные; даже это не создаёт8различных benefit.

## quality_acts

Grain: действующий QA-акт × проверенный объект; ключ `act_id`. **Единица независимости — `inspection_id`**, а не число строк. `case_id/event_id` — проверенный случай/событие (null у намеренно чужого старого акта F04). `subject_id`, `scope` personal/team/process — область применимости, не автоматическая личная оценка любого адресата. `criterion`, `scale`, `scale_version` — содержание и шкала. `minor/major/critical` — число подтверждённых нарушений совместимой penalty-редакция; для чужой шкалы могут быть null и не восстанавливаются из score. `score` — оценка акта в **его** шкале. Сырые97/100 и4/5 не являются одной метрикой.

`sample_method` — как отбирались объекты; `coverage_object` — что покрывает один акт. В базе census_of_scenario_work_register проверяет каждый отдельный случай; не означает покрытие всего потока настоящего банка. В F04 один отдельный акт97/100 по communication-редакция дополняет совместимые98/100, S02 имеет лишь6актов другого scope/неизвестного отбора и один чужой актP0. `checked_at` — дата первоначальной проверки; `observation_start/end` — горизонт последствий; `finalized_at` — дата итогового завершения акта после дозревания, до которой он не выдаётся за итоговое качество. `checker_id`, `evidence_status` — происхождение/доступность. `existing_activity=true`, `existing_minutes=3` — ранее выполнявшаяся QA-деятельность и сценарная норма на акт; повтор одного inspection не расходует новый акт автоматически.

## approvals_audit

Grain: решение/проверка × версия; ключ `approval_id`. `beneficiary_id`, `beneficiary_role`, `beneficiary_team` — получатель и зависимости. `action`, `source_ref`, `before/after`, `reason` — что редактировалось/проверялось и почему; это ссылки/версии источников, а не готовая сумма. `initiator_id` — кто заявил, `input_editor_id` — кто менял вход, `signer_id` — кто подтвердил, `operator_id` — кто готовит проводку. `signer_reporting_to`, `operator_reporting_to` — доступные связи подчинения; null в базе означает отсутствие указанной связи в данном сценарном регистре. `alternate_signer_id`, `alternate_operator_id`, `appeal_owner_id`, `signed_at` — доступные заместители/апелляция/дата. Часть полей намеренно отсутствует в отдельной F06 записи; это пробел, не скрытое independent=true. В F09 self ID совпадает на трёх этапах; наличие заместителя ещё не означает его фактической подписи.

## comparison_registry

Grain: заранее зарегистрированная единица соревнования × квартал; ключ `registry_id`. `comparison_group_id`, `registered_at` — замороженный состав группы, не сортировка по исходу. `eligible_unit` employee/team. `home_pool_id` — единственный домашний пул. `window_id/cohort_id` — фиксированное окно/когорта; личные записи членов команды находятся в team_members и не создают дополнительные командные единицы. Ни рангов, ни пула денег в таблице нет.

## source_manifest

Grain: таблица/класс выгрузки × ожидаемая партиция периода; ключ `partition_id`. `table`, `period_id`, `partition_ref` — ссылка на конкретную часть base/развёрнутого варианта, не внешний API. Для periodless справочников одна и та же общая таблица доступна обеим партициям; это повтор ссылки, а не два независимых набора данных. P0 quality-партиция ожидаемо пустая в базе, содержит1старый акт только в F04.mixed.

`source_version`, `generated_at` — версия/дата формирования; не дата публикации реального исследования. `expected_count` — ожидаемые **физические строки** этой версии, включая известный точный дубль F05; `received_count` — реально полученные строки; уникальные ключи дополнительно проверяются структурно. `received_sha256` — SHA256 canonical pretty JSON массива с sort_keys=True, indent=2, UTF-8/ensure_ascii=False и завершающим newline. Порядок массива сохранён для контроля именно файла, а не как показатель заслуги. `availability` available/lost_partition/restored/known_unusable_before_start. `expected_before_start` и `readiness_at` — что было известно до усилия; `missing_reason` — видимый контрольный статус пропуска. Причина происшествия вне видимого кода и восстановленные факты без источника не выдаются алгоритму.

Patch обновляет количество/хеш для всех изменённых партиций; в lost/known_gap ожидаемое число сохраняется, получено0. В restored данные те же, но версия/дата получения поздняя. Получено0 при available/expected0 означает наблюдаемое отсутствие строк, а не потерю. Выгрузка без данных не является набором QA0.

## resource_assumptions

Grain: вид деятельности × сценарная норма; ключ `activity_id`. `role`, `minutes_per_unit`, `unit`, `frequency` задают роль/минуты/знаменатель и периодичность: case, source_class, partition, subject_period, exception, lost_partition, new_reviewed_case. `existing_activity` отделяет действующий QA от настройки/новых проверок; `source` явно обозначает допущение. Объёмы нужно выводить из соответствующего количества применимых единиц; строки этой таблицы не подтверждают фактические свободные часы/экономию ОТП.

## Patch и файлы

`scenario_index.json` перечисляет `scenario_id`, `title`, `variants`, `patch_ref`, `baseline`. В `patches/Fxx.json`: `variants` — словарь массивов операций, `grain` — первичный ключ таблицы, `key` — однозначно адресуемый ключ, `op` — update/insert/delete/append_export_copy; `set` — изменения полей, `row` — вставляемая полная строка. Чтение не смешивает варианты/не применяет все изменения сразу. Повторная доставка patch не новая награда: парные снимки всегда начинаются с базы.
