# Основания настройки и адаптации

Проверено 26.10.2026. Ниже отделены документированные механизмы Codex и наша организация исследовательской работы. Пути и схемы ролей зависят от актуальной версии клиента.

## Официальная документация OpenAI: прочитанные страницы

| Страница | Что проверено и использовано |
|---|---|
| [Custom instructions with AGENTS.md](https://developers.openai.com/codex/guides/agents-md) | Инструкции обнаруживаются по иерархии директорий; более близкие к рабочей папке идут позже. Без найденного корня проекта проверяется текущая директория. Поэтому запускать работу из корня этой папки, а локальные правила открывать для нужной области. |
| [Agent skills](https://developers.openai.com/codex/skills) | Проектные навыки размещаются в `.agents/skills/<name>/SKILL.md`; нужны `name` и `description`. Метаданные выбираются раньше полного текста; ресурсные файлы читаются по необходимости. |
| [Config basics](https://developers.openai.com/codex/config-basic) | Проектные переопределения — `.codex/config.toml`; проектные `.codex/` слои требуют доверия к папке. Не меняем глобальный `~/.codex/config.toml` и настройки разрешений. |
| [Subagents](https://developers.openai.com/codex/subagents/) | Project custom agents — отдельные `.toml` в `.codex/agents/`; обязательны `name`, `description`, `developer_instructions`. Разрешения наследуются; текст «read-only» не создаёт отдельную песочницу. Делегирование требует соответствующего поручения или применимых инструкций; файл роли сам не запускает работу. |
| [Analyze datasets and ship reports](https://developers.openai.com/codex/use-cases/datasets-and-reports) | Официальный пример работы с данными: конкретный вопрос, профиль входов, пропуски и ключи, прозрачные преобразования, интерпретируемый анализ, проверяемый отчёт и ограничения. Страница описывает ChatGPT Work; переносим принципы анализа, не предполагая наличие перечисленных там plugins в этом проекте. |

Это ссылки на реально полученные страницы, а не только поисковые описания. Официальный пример интерактивного dashboard также просмотрен; его Sites, подключения и расписания не применяются, потому что задача — подготовка файлового процесса решения кейса.

## Собственные проектные соглашения

`project/`, `research/`, `analysis/`, `deliverables/`, CSV-реестры, статусы утверждений и шаблоны — наша адаптация. Codex не создаёт и не поддерживает эти реестры автоматически. Обязательного набора ролей, универсального конвейера или требования создавать wiki из документации не следует.

По согласованной архитектуре установлены шесть профилей и семь новых skills в дополнение к knowledge-curation. Поле `agents.max_concurrent_threads_per_session` задаёт два дочерних потока, не считая основного; оно подтверждено в прочитанной странице Subagents. Модели, MCP и разрешения не переопределены. Имена ролей, две ветки, три итерации, рубрика и snapshot_store — проектные соглашения, а не встроенный автоматический конвейер Codex.
