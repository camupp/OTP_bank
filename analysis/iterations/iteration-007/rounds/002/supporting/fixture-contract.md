# Iteration-007: контракт общего синтетического набора источников

01.11.2026. Подготовительное описание, **не данные банка, не готовая концепция и не исполняемый тест**. Координатор фиксирует конкретные сценарные значения/файлы до разработки кандидатов и применяет одну версию к четырём новым вариантам и неизменённой CON-016@v2. Подбирать входы, пороги или контрольные исходы после просмотра кандидатов нельзя. Основа: [D-022](../../project/decisions.md), [карта источников](metric-source-design/README.md), MS01–MS07; родитель — CON-016 §2, §5–8; [review006](../iterations/iteration-006/rounds/001/review.md), строки 5,14,44–48. Первичные банковские системы/QA не проверены.

## Размер, единицы и границы

Минимальный набор: три семейства (поддержка, бэк-офис, проектная IT/аналитика), по две сравниваемые единицы внутри семейства, два последовательных фиксированных квартала одного годового окна. Потоковые единицы — работники, проектные — две команды с поимёнными долями. Дополнительные строки новичка/0,5FTE и отводимого руководителя/HR допустимы как заранее определённые варианты тех же случаев. Сопоставимые группы и реестр участников закреплены; малое n и нулевые/незаполненные top-слоты сохраняются. Это тест расчёта, не репрезентативная выборка и не замена N7200 в экономике.

Нужны: небольшой читаемый manifest случаев; фактические строковые события; компактные агрегаты субъект×период; ссылки/хеши. Для потоков можно детерминированно развернуть шаблоны в сотни событий, чтобы честно проверить минимумы родителя (100/80 единиц, 20 случаев, 10 дней). Нельзя выдать строку `count=100` за 100 независимых QA-актов или 20 уникальных случаев. Проектный контраст «один принятый крупный результат / восемь частей того же результата» намеренно может не пройти старый минимум 8 закрытий; старый вариант не исправляется ради прохождения.

Конкретные численные сценарии, веса, справочники и таймзона — **допущения fixture**, не нормативы ОТП. Все normal/stretch, окна дозревания, версии QA и минимумы кандидаты задают проспективно, до расчёта итогов. Fixture включает и обычный достаточный случай, и пограничный, и отказ; не состоит только из атак на родителя.

## Два слоя информации

**Доступно расчёту:** только перечисленные выгрузки и заранее замороженные правила кандидата. Поле может быть nullable/отсутствовать в конкретном источнике. Автоматически считать отсутствие нулём, успехом или провалом нельзя. Один и тот же доступный пакет выдаётся всем; необязательные поля нельзя «дозапросить» только победителю.

**Контроль проверяющего (oracle):** сценарный root события, что было изменено в парном случае, намерение попытки манипуляции, известный проверяющему факт недокументированного использования/помощи, причина потери выгрузки. Это не поле расчёта и не тайная ожидаемая сумма награды. Если факт отсутствует в доступных источниках, честный результат может быть `not_computable`/отложенная проверка; нельзя требовать угадывания истины. Проверяющий не выдаёт oracle как дополнительное идеальное банковское поле. `impact_score`, «истинная ценность работника» и готовый правильный Q запрещены в обоих слоях.

## Обязательные случаи и парные изменения

Таблица задаёт свойства проверки, **не победителя и не фиксированную награду**. Базовый случай каждого семейства содержит достаточно полей для хотя бы одного честного правила; сверх этого есть явные пробелы. При проверке достаточности кандидаты сохраняют собственные заранее раскрытые нормы.

| ID | Сценарий доступных источников | Что должно быть видно в результате проверки |
|---|---|---|
| F01 | Обычный качественный результат обоих кварталов; рядом более сильный сопоставимый результат. | Воспроизводимость normal/stretch/top и награды; назван период, знаменатель, качество, конкуренция и дата права. «Сильный» здесь описание сценарного изменения результата, не готовая метка для алгоритма. |
| F02 | Тот же результат/график; worklog увеличен переработкой или уменьшен неполным заполнением. | Рост/снижение записанных часов сам по себе не улучшает заслугу. Если мощность без этих часов неизвестна — явный предел расчёта. |
| F03 | Done без приёмки/использования; рядом принятый используемый результат; поздняя приёмка за quality-close. | Статус не заменяет полезный результат; дата/недостаточность доказательства отражена, поздний исход не приписан раннему периоду задним числом без правила. |
| F04 | QA97/100 по одной схеме и 4/5 по другой, неравное покрытие/тематика; CSAT: три ответа против большой выборки и отсутствие ответов. | Не усреднять несовместимые шкалы и не ранжировать по трём пятёркам; знаменатели и допустимое использование каждого акта видимы. Нет ответа не ноль. Полнота QA не равна большому числу CSAT. |
| F05 | Дубли выгрузки, reopen/повтор/переделка одной причины и ошибочно новые case_ID. | Дедупликация по доступным связям; отсутствие связи честно ограничивает вывод. Нельзя дважды наградить один root в обычном результате и special без добавочной пользы. |

| F07 | Один крупный принятый проектный результат и то же содержание, разбитое на восемь задач, с одинаковыми приёмкой/использованием/дефектами. | Дробление не создаёт заслугу. | F12 | Массовая ничья/мало участников, смена команды/FTE, различная доля командного вклада; сохранён один benefit/root. | Не размножаются места/пулы/годовые окна; пустые слоты не перенормируются; одна командная сумма, неизменная личная когорта/права. Парные изменения F02/F05/F07/F08 выполняются при прочих равных и сохраняют исходную версию. Порядок строк/ID там, где ID не несёт содержания, не должен менять результат; для хеш-выборки родителя переименование ID проверяется отдельно как изменение входа, а не требование неизменной выборки. Перестановка строк и повтор той же выгрузки обязаны давать тот же учёт. Изменение реального качества/приёмки вправе менять результат.

## Общий формат результатов и проверки

Для каждого candidate×case×subject×period: `rule_version`, входные source_refs, пригодность группы/источника, numerator/denominator/units либо шаги алгоритма, quality_scope/coverage, data_status (`sufficient`/`insufficient`/`source_incident`), normal/stretch/top и объяснение, reward_status (`earned`/`not_earned`/`pending`/`not_computable`), сумма/окно/дата, подписи/отвод, добавленные минуты по ролям. Не сводить четыре статуса к одному нулю. Недостаточность данных сама по себе не создаёт право на G.

Проверяющий независимо воспроизводит результат, сравнивает парные случаи и сохраняет расхождение с причиной: иной допустимый смысл метрики; недостающее поле; ошибка алгоритма; нарушение наградного/валютного инварианта. Исправление опечатки отличается от изменения механизма/порога. Неизменённую CON-016 рассчитывают буквально; нет входа для её Q/QA — `not_computable`, без скрытой адаптации/нового аудита.

Ресурс: отделить уже созданные действующие QA-акты от настройки выгрузки/расчёта, проверки полноты, независимой подписи, исключений и нового контроля. Минуты — сценарные допущения с объёмом; не объявлять весь прежний QA новым расходом, весь переиспользованный QA бесплатной мощностью, а экономию минут — доказанной экономией банка. Масштабирование на N7200 и E24 проверяется отдельно финансистом на общей основе, без умножения маленькой тестовой группы в прогноз мотивации.

Итог общей проверки: матрица покрытых/невычислимых случаев, конкретные нарушения/проходы инвариантов, новые данные/труд, источник ограничения и границы уверенности. Количество пройденных случаев не автоматический рейтинг; слепой reviewer применяет frozen rubric. Добавление нового случая после просмотра кандидатов допустимо только как общая явно обозначенная проверка/следующая версия, а не тихая подстройка.

Незавершено: конкретные синтетические строки/значения, deterministic generator при необходимости, frozen manifest/hash и независимый расчёт. Они не созданы этой запиской. Реальные банк-интервью, запуск систем и доказательство эффекта не являются условиями завершить проектное сравнение.
