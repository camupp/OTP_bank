# Проверка качества и границы валидации

## Для содержательной порции

- **Атрибуция:** значимые утверждения связаны с конкретными источниками и местами. Отредактированный пересказ не оформлен как точная цитата.
- **Глубина:** аннотация, поисковое описание и полный текст различаются. Наличие скачанного PDF само по себе не означает полного чтения.
- **Смысл:** сохранены определения, условия, исключения, единицы и периоды; важный числовой пример проверяется по оригиналу. Из OCR не восстанавливаются нечитабельные числа догадкой.
- **Противоречия:** видно, какие источники и определения расходятся; причины, которые не установлены, остаются гипотезами.
- **Структура:** страница отвечает самостоятельному вопросу. Информация из нескольких материалов объединена без потери атрибуции; схемы сохраняют связи элементов.
- **Охват:** статус и scope соответствуют реальному результату; архивы, производные и технические файлы не увеличивают число независимых доказательств.
- **Границы:** wiki хранит подготовленные знания; новые финансовые расчёты и выбор концепции относятся к отдельному анализу.

## Структурная команда

Из корня проекта:

```text
python3 .agents/skills/knowledge-curation/scripts/validate_wiki.py --project-root .
```

Проверяет CSV-заголовки, ID, перечислимые статусы, существование путей, ссылки Markdown, источники страниц и выходы завершённых порций. Читает созданные wiki-файлы и метаданные зарегистрированных путей, не извлекает raw и не создаёт контент. Пустой каркас допустим и явно отражается в счётчиках.

Опция `--verify-source-hashes` дополнительно читает байты только зарегистрированных файлов raw и сравнивает версии. Это проверка целостности, не смысловая обработка. По умолчанию чтения содержимого raw нет.

Успешная команда не доказывает истинность утверждений, полноту смыслового переноса, корректность номера страницы, непересечение всех scope или удачность таксономии. Эти проверки выполняет агент по порученной порции и описывает в отчёте.

## Будущая проверка поведения skill

Сейчас поведенческие пробы не выполняются по просьбе пользователя. После отдельного поручения полезны примеры: первичный кейс; обзор со ссылками; аннотация без полного текста; конфликт чисел; уже разобранная тема учебника; источник новой версии. Для каждого проверять происхождение знаний, отсутствие выдуманных деталей, полезность структуры и продолжение с сохранённой точки.
