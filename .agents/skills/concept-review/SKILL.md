# Независимая проверка концепций


Прочитай только назначенный review-packet, общие проверенные входы и рубрику. Авторство, прежние ранги, приватная карта и lineage в первичную оценку не входят.

1. Проверь обязательные gates по `.agents/skills/case-iteration/references/review-rubric.md`, опираясь на исходники и приложенные финансовые проверки. Отметь неопределённость; отсутствие найденной ошибки не равно доказательству.
2. Оцени все варианты, baseline и прежний лучший вариант по одной рубрике с наблюдаемыми основаниями. Сначала оценка сама по себе; после её сохранения можно отдельно получить сравнение изменений.
3. Не назначай преимущество только за новизну, длину текста или высокий суммарный балл. Улучшение должно выражаться в устранённой ошибке, более сильных основаниях, пользе при сопоставимых ограничениях или устойчивости.
4. Верни review.json и review.md по контракту: gates, критерии, конкретные замечания, шортлист и основания. Вариант с fail/uncertain по обязательному gate не допускается как подтверждённый победитель.
5. Разрешён результат «все требуют доработки». Не редактируй концепции и не предлагай незаметный гибрид как уже проверенный вариант. Выбор после проверки фиксирует координатор.

Оценки 0–3 — экспертная рубрика, не измеренный бизнес-эффект. Формальная проверка JSON не заменяет проверку фактов и расчётов. Работай в назначенной области, не запускай собственных исполнителей.
