## Доступ и неизменность

Общий контекст: этот файл, `dictionary.md`, `assumptions.csv`, `business-config.json`, `reader.py`, `source/`, `patches/`, `manifest.json`, `manifest.sha256`. `coordinator-only/` содержит только подготовительный генератор, структурную проверку и их отдельный manifest; его не назначают разработчикам. Reader не импортирует эти файлы и не вычисляет проектные показатели.

Старый fixture **не скопирован и не изменён**. Его корень нужно передавать явно. Сохранённый SHA256 старого `manifest.json`: `2a8d8effe027296dd4a0b52a2717b2c8ac2dc75303af3f1bf56f8f8540ad3edc`. Общий manifest перечисляет SHA/размер всех новых доступных файлов, кроме самого manifest и файла его SHA, а также всех используемых доступных членов старого пакета. Сам SHA manifest находится в `manifest.sha256`. Из него исключены coordinator-only и временный Python bytecode. Денежные основания не читались и не изменялись; их неизменность проверяет координатор отдельно.

После freeze менять пакет нельзя; содержательное исправление требует новой версии и нового fingerprint. Общие допущения о кадровом резерве и оплате из common-checks не становятся фактом доступности ресурсов из-за существования этих источников.

## QA, проекты и сроки

В полной R1 у каждого потокового человека среднее QA99: ровно половина актов98/minor1 и половина100/minor0. Каждый проектный root состоит из двух исходных частей с такими же98/100 и двумя различными inspections; grain результата остаётся root. Все части покрыты по отдельности. Один из актов не называется whole-act; готового доказательства покрытия root одной частью нет. Измерение качества на root кандидат должен описать сам, сохранив scope и точность. В независимом полном roster editor, signer, operator различаются и не входят ни в одну группу получателей.

Проспективный `business-config.json` задаёт рабочие обязательства. Для аналитического пакета срок предрассылки —20.03/19.06 в12:00, заседания —27.03/26.06 в12:00. Заблаговременная готовность нужна для одного запланированного цикла проверки до заседания; дополнительная польза от любой ещё более ранней даты не предполагается. T01: за1день до предрассылки; T02/T03: ровно на сроке; T04/T05/T06: после предрассылки, до заседания; T07/T08: после заседания. Версия2 смягчает именно срок заседания после старта; она явно конфликтная. Понятие110%от одного бинарного решения не вводится.

Для неизменного legacy-source есть отдельные конфигурации на группы G-support/G-backoffice/G-project: поддержка108ед. и бэк80ед. из **его** проспективной мощности/страт, workflow100 из нового явно вымышленного делового плана. Они доступны любым лицам соответствующей группы/периода, без правил поIDработника. Это общие предположения round002, `does_not_amend_legacy_source_rule=true`: историческое отсутствие проектного стандарта и минимум8закрытий прежней концепции не исправлены. `business_configs(group, period, work_type, version=1)` возвращает подходящие версии либо явный пустой список; без work_type у R2-G-project есть альтернативные workflow/analytical-конфигурации, поэтому тип нужно выбрать явно. Для R4 нет бизнес-целевой конфигурации: это тест календаря. Версию2 можно получить только явным `version=2`, её наличие не означает принятия конфликта.

Для R4 личное годовое окно начинается15-го месяца когорты2026 и заканчивается за1день до следующей годовщины. Кварталы начинаются с шагом3месяца внутри **того же** окна, найм/перевод не сдвигает окно. Интервал работы `[start 00:00:00, next_start 00:00:00)`; `quality_close_at` явно12:00 на дате end+28дней и включительно. Partition-label — выгрузочная метка вокруг границы, а не готовое решение о принадлежности события кварталу. Соседние snapshot-partitions могут содержать события на той же границе с разными ID; связывать их по source-case, а не суммировать метки периодов.

## Воспроизведение и ограничения

Только координатор: `/opt/homebrew/bin/python3.12 coordinator-only/generator.py --old-fixture-root /explicit/path/to/fixtures --verify`. Без `--verify` команда пересоздаёт **только этот addendum**, поэтому после freeze используйте только verify. Проверяются детерминированность повторной подготовки, PK, case/event refs, counts/SHA партиций, совместимость penalty, размеры групп/команд, подписи полной панели, независимые источниковые роли, одинаковая плановая мощность, единицы/диапазоны R1, проспективность v1 и раскрытие всех23старых вариантов. Подготовительный инструмент не исполняет проверки C2–C7 над концепциями.

Batch-metadata — пример подписанного состава реестра с версией, roster/member hashes, approval refs и исключениями. Он не требует от концепций конкретной технологии пакетного контроля, не доказывает полномочия подписанта и не заменяет проверку индивидуального конфликта. Receipt — проектное допущение о различимых времени факта и доставки. Наличие полей не доказывает доступность таких источников/мощности у банка. В R4 нет полной совокупности9когорт на39месяцев, связей с реальными магазинами, денежными регистрами или инфраструктурой.
